# 공고 탐색 품질 점검 — 2026-10-15

## 2026-10-20 마감 공고 메일 혼입 수정

- 지난 접수기간과 `마감 (~날짜)` 표기가 `JobAlerts.collect`를 통과하는 실패를 2개 테스트로 재현했다. `접수기간`을 표에는 표시하면서 마감 판정에서는 읽지 않던 불일치였고, 단독 `마감되었습니다`도 놓쳤다. 기존 테스트는 한 가지 ISO 날짜만 검사해 이런 경우를 잡지 못했다.
- 공통 검색 필터는 한국어/점/슬래시 날짜, 접수기간의 종료일, 명시 마감 상태를 처리한다. 게시일은 만료 근거로 쓰지 않는다. 프로젝트 메일은 추가로 공개 상세 원문에서 접수상태를 확인하며, 원문 미확인 후보는 보류한다. UI/Agent 1의 검색 목록 전체가 현재 접수 중임을 검증한 것은 아니다.
- 발송 이력의 URL 60개를 현재 시점에 읽기 전용 점검한 표본은 진행 근거 13개, 마감 근거 28개, 미확인 19개였다. 최근 30개만 보면 각각 11/11/8개다. 이는 **10월 20일 관찰 상태**이며 발송 당시 상태를 소급 확정한 수치가 아니다. 미확인에는 차단 응답과 미지원 주소도 있다. 제보된 카드사·7월 직무와 일치하는 캐치 후보가 실제 발송 이력과 재검색에 포함됨을 확인했다. 메일 본문은 연결 재인증 문제로 직접 읽지 못했다.
- 수정 후 기존 알림 조건의 실제 검색 응답 266개를 재생하고 현재 원문을 다시 확인했다. 검색 단계 마감 제외 30개 → 원문 확인 72개 중 마감 제외 24개·미확인 보류 17개 → 진행 근거가 있는 공고 30개 선택. 제외 수는 수집 후보 기준이며 동일 공고가 검색어별로 중복 집계될 수 있다. 설정 상한에 도달하여 나머지 후보는 확인하지 않았으며 전체 재현율을 뜻하지 않는다. 메일 발송과 기존 수신 설정·발송 이력 변경은 하지 않았다.
- 증빙은 ignored `result/search_quality/deadlines-20261020/`에만 보관한다. 실제 원문 표본과 함께 기간 만료·오래된 게시/현재 진행·검색/원문 모순·미확인 보류·한국 시간 마감·실제 메일 조립/미발송 경계 회귀 테스트를 유지한다.

## 결론

기존 검증은 모의 공고 몇 개의 필터·메일·화면 동작을 확인했지만, 사이트별 수집량·회사명 보존·비공고 혼입·원문 대비 누락을 측정하지 않았다. 수집 설계에도 병목이 있었다. UI는 5개 도메인을 한 Tavily 검색에 넣고 **합계 12건**만 받았다. 알림은 플랫폼별로 나눴지만 여러 직무·지역·기술·연도를 한 검색어로 묶었고, 검색 요약만 필터링했다. 테스트 통과가 탐색 품질을 뜻하지 않았던 이유다.

## 재현과 관찰

| 점검 | 관찰 | 해석 |
| --- | --- | --- |
| 사이트별 가상 공고 10개 × 5개 사이트 | 기존 12/50건, 수정 후 50/50건 | 합산 상한으로 인한 프로그램 내부 누락 재현·해결. 실제 플랫폼 재현율 수치가 아님 |
| 기존 실제 혼합 검색 | 원시 결과 10건, 기업명 표기 3개 | 목록 페이지·점핏 등 별도 서비스도 혼입 |
| 같은 기존 검색어를 사이트별로 실행 | 사이트별 12건씩 총 60건 | 검색을 나누는 것만으로 후보 수가 달라짐. 중복·마감·적합성 판정 전 수치 |
| 색인 수집 확대·분류 점검 | 잡코리아의 20건 중 유효 후보가 1건뿐인 사례 | 상한 확대만으로는 검색 목록 중심 색인 문제를 해결하지 못함 |
| 잡코리아·사람인 원문 검색 우선 적용 | 30건 수집 → 지역 표기 1건 제외 → 29건, 회사명 미확인 0건 | 공개 검색 카드의 제목·기업·조건을 읽은 실제 표본. 전체 페이지나 엄격한 경력 조건 검증은 아님 |

직접 검색의 공개 화면을 5개 사이트에서 확인했다. 잡코리아에서는 법률사무소 새율·퍼플아카데미·빗썸·티엠씨케이·메가스터디교육 등이 보였고, 원문 수집 결과에서도 확인했다. 사람인은 카드의 `corp_name`에서 회사명을 읽어 `[분석팀]` 같은 제목 표기를 회사로 오인하지 않도록 했다. 캐치는 검색 결과 로딩 완료 후 5건이 표시됐다. 원티드에는 연관 추천을 포함한 1000건 표시가 있었고, 잡코리아·사람인에도 광고·확장 검색이 포함됐다. 이 화면 건수들을 서울·경기/신입·무관·1~5년의 적합 기업 수로 간주하지 않았다.

실시간 값은 검색 시점·정렬·광고·필터에 따라 달라진다. 위 점검들은 검색어와 수집 방식이 다른 실험도 포함하므로 전체 재현율이나 성능 배수로 환산하지 않는다. 기업명 표기의 고유 개수도 동일 기업의 법인명·브랜드 별칭 때문에 실제 고유 기업 수와 다를 수 있다.

## 수정한 수집 방식

- `core/native_jobs.py`: 잡코리아·사람인·인크루트의 공개 검색 HTML 카드를 우선 읽고, 카드의 근무지·경력·지원 버튼을 `requirements_card`로 남긴다. "A OR B" 검색어는 사이트 검색창에 글자 그대로 넣지 않고 대안별로 나눠 검색한다. 로그인·쿠키·스크립트 실행·내부 API는 사용하지 않는다. 리디렉트·차단·레이아웃 변경·과대 응답은 무시하고 색인 검색으로 대체한다. 각 카드의 회사와 직무를 연결하고 관련 없는 광고를 거른다.
- `core/postings.py`: 직무 대안을 최대 3개 검색어로 분리한다. 더 많은 대안은 마지막 OR 검색에 보존하며 버리지 않는다. 오래된 알림의 공백으로 이어진 데이터/사이언티스트/ML/AI 직무도 분리한다. 지역 목록을 전부 포함해야 하는 검색어와 연도·기술을 모두 강제하는 검색어를 피한다.
- Agent 1의 `search_jobs`도 같은 수집기를 사용한다. 기존의 요청 직무 무시, 2026년 5월 고정, 인크루트 누락, 본문에 `마감`이라는 글자가 있다는 이유만으로 정상 공고까지 제거하던 별도 경로를 없앴다. 경력 요청은 결과에 보존하되 검증하지 않은 경력 조건을 통과했다고 표시하지 않는다.
- UI는 Tavily 색인을 사이트별·검색어별 최대 20건, 원문 검색 카드를 최대 100건까지 함께 수집하며 최대 3개 요청을 동시에 처리한다. 전체 최대 300건 후보, 중복 제거 후 최대 100건 표시. 5개 사이트/여러 직무는 최대 15회 Tavily 요청이다. 비용이나 외부 노출 범위를 숨기지 않는다.
- 목록·다른 서비스·명시된 과거 마감·명시적 종료를 구분한다. 연도 없는 날짜를 현재 연도로 추정하지 않는다. 모바일/데스크톱·추적 URL은 알려진 공고 ID로 정규화한다. 기존 발송 이력도 같은 기준으로 비교한다.
- UI와 메일이 회사명 근거·영어 단어 경계·지역 검사 규칙을 공유한다. 원문 텍스트가 있으면 짧은 요약보다 먼저 사용한다. 회사명 미확인은 그대로 남기며, 기업·브랜드 표기를 법인 검증 결과로 표현하지 않는다.
- 작은 출력 상한에서 한 사이트/한 회사의 여러 공고가 모두 차지하지 않도록 서로 다른 기업을 먼저, 사이트별로 번갈아 배치한다. 메일의 기존 상한과 수신 설정은 변경하지 않는다. 수집·조건 통과·선택 수와 키워드 근거 부족 건수를 상태/미리보기에서 확인할 수 있다.

## 검증과 재현

`test_search_quality.py`는 5개 플랫폼의 독립 수집 예산, 영어 키워드 오탐, 여러 직무 보존, 목록/다른 서비스 혼입, 모바일 중복, 명시 마감, 기업명/부서명 구분, 부분 실패, 기업 다양성을 검증한다. `test_native_jobs.py`는 카드별 기업 연결, 스크립트/쿠키 미사용, 광고 제외, 레이아웃 실패와 색인 대체를 검증한다. `test_job_hunter_search.py`는 Agent 1의 요청 직무·5개 플랫폼·미검증 경력 표시를 검증한다. 알림 테스트에는 출력 상한 진단과 긴 원문의 키워드 근거를 추가했다.

```powershell
# 비용 없는 회귀 테스트
uv run python -m unittest discover -s tests -p "test_search_quality.py"
uv run python -m unittest discover -s tests -p "test_native_jobs.py"

# 로컬 소유자의 키로 실제 점검: 명시 실행 시에만 네트워크/API 사용
uv run python -m job_agent.examples.retrieval_audit --live --role "데이터 분석가" --location "서울, 경기"
# 위 명령이 출력한 파일로 비용 없이 재현
uv run python -m job_agent.examples.retrieval_audit --replay result/search_quality/audit-실행시각.json
```

원시 검색 응답과 비교 화면은 Git 제외 `result/search_quality/`에 보관한다. 감사 도구는 메일·LLM·개인 이력서·계정 설정을 조작하지 않는다. 공개 Vercel은 기존대로 직접 입력만 정리하며 운영자 키로 검색하거나 메일을 보내지 않는다.

## 남은 품질 한계와 다음 검증

1. 캐치·원티드의 원문 검색 어댑터는 미구현이다(목록이 JavaScript 전용). 원티드는 상세 페이지의 `__NEXT_DATA__`로 접수 상태를 확인하지만 후보는 색인 검색에 의존한다. 현재 색인 검색은 최신 공고 누락을 보장 없이 줄이는 후보 수집 경로다. 5개 플랫폼의 전체 결과를 대체했다고 표현하면 안 된다.
2. 잡코리아·사람인·인크루트는 검색어마다 최대 3페이지를 읽지만 잡코리아 검색은 지역 필터가 적용되지 않아 광고가 섞인다. 사이트 변경/차단에 대비해 결과의 수집 출처와 실패를 구분한다. 검색어별 첫 페이지 표본을 넘어서는 수집이 필요하다.
3. 지역은 카드/요약에 있는 표기를 검사한다. 경력 1~5년과 세부 직무는 정형 원문 근거로 종단 검증하지 않았다. 프로젝트 메일은 원문 접수상태 확인을 추가했지만 검색 목록 전체에는 적용하지 않는다. 원문 차단/마감 미확인 후보는 메일에서 보류되어 누락될 수 있다.
4. 다음 품질 검증은 같은 시점·검색어·지역·경력·정렬의 사이트별 원문 20~50개를 검수한 기준 집합으로 고정하고, 공고 ID 일치율·적합 공고 비율·고유 기업 누락·회사명 누락·명시 마감 혼입·호출 수를 측정해야 한다. 실제 응답을 재생해 기능 테스트와 수집 품질 테스트를 분리한다. 현재 전체 재현율은 미측정이다.
