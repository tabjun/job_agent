# 2026-10-15 코드 리뷰와 UI 개선

검토 범위: 로컬 UI/API와 공개 요청 처리 경계, 이력서 입력 검수와 사이트 저장 재확인, 공고 검색·메일·예약 처리, 공용 모델/도구 실행 엔진. 정적 검토 및 가상 자료의 로컬 재현이며 실제 채용사이트·SMTP·유료 API의 운영 성공을 인증하지 않는다.

## 남은 기능 개선

- **[해결] 짧은 영어 키워드의 부분 일치 오탐.** `AI, R`이 `email career 안내`에 일치하던 UI/알림 로직을 `core/postings.py`의 단어 경계 검사로 통합하고 회귀 테스트했다. 후속 [공고 탐색 품질 점검](search_quality.md)에서 수집 예산·원문 검색·회사명·모의 테스트의 한계도 함께 개선했다.
- **[P2] `job_agent/core/engine.py:166` — 미등록 도구 호출에 대응하는 ToolMessage가 없다.** 모델이 `missing_tool`을 요청하면 경고만 출력하고 `{"messages": []}`를 반환한다. 다음 모델 턴에 해결되지 않은 tool-call ID가 남아 도구 응답 계약을 깨뜨릴 수 있다. 해당 ID의 오류 ToolMessage를 반환하고 회귀 테스트를 추가해야 한다. 모의 호출로 응답 누락 확인; 이번 변경에서는 엔진 프로토콜을 수정하지 않았다.

## 이번에 수정한 문제

- **[P1] SMTP 보안 설정 오타 시 암호화 누락**: `ALERT_SMTP_SECURITY`가 `starttls`·`ssl` 외의 값이면 기존 코드는 일반 SMTP 연결 후 TLS 없이 로그인/발송할 수 있었다. 앞뒤 공백과 대소문자를 정규화하고 허용 값 외에는 네트워크 연결 전에 중단한다. STARTTLS → 로그인 → 발송 순서와 SSL 연결을 모의 SMTP로 검증했다.
- **[P2] 같은 제목의 서로 다른 공고 누락**: 제목을 발송 이력의 식별자로 사용해 다른 기업이나 별도 채용 건도 제외했다. URL을 중복 기준으로 사용하도록 변경했다. 같은 제목의 기업 A/B 및 A의 별도 공고를 모두 유지하고, 재실행에서는 같은 URL을 다시 보내지 않는지 검증했다. 다른 URL에 게시된 실제 동일 공고는 중복될 수 있으므로 문서에도 명시했다. 이전 저장 파일의 `sent_titles`는 읽기 호환성을 유지하며 필터에 사용하지 않는다.

## UI 변경

- 흰 바탕, 중립적인 회색 사이드바, 남색 브랜드와 인디고 강조색으로 녹색 중심 팔레트를 교체했다.
- 안내, 처리 모드, 입력, 공통 이력서 항목, 플랫폼 연결, 알림 조건, 결과를 테두리·여백·옅은 배경의 카드로 구분했다.
- 단계별 아이콘·번호, 버튼·입력 포커스, 현재 메뉴의 `aria-current`를 보강했다. 모바일에서는 카드와 폼이 한 열로 정리된다.
- 첫 사용 안내 이미지는 새 화면으로 갱신했다. 기존 기능 시연 이미지는 이전 디자인이라는 안내를 붙여 실제 실행 기록을 보존했다.
- 로그인·동의·검수·저장 승인·공개 모드 차단 정책은 유지했다. 기존 사용자 변경 및 개인정보 파일을 덮어쓰지 않았다.

## 구조 개선 제안

- 검색과 알림에 중복된 키워드·지역 처리 규칙을 공용 순수 함수로 모으면 화면별 결과 차이를 줄일 수 있다.
- `pyproject.toml`의 배포 이름과 설명은 아직 `langchain-example` 실험용 문구다. 패키지 이름 변경은 설치·잠금 파일·배포 영향까지 검토한 별도 변경으로 진행하는 것이 좋다.
- 마감·지역·경력 판단은 검색 요약에 의존한다. 정확한 조건 판정이 필요하면 근거 출처와 확인 상태를 포함한 정형 공고 스키마부터 추가해야 한다.
