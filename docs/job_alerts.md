# 공고 알림 메일

## 두 가지 메일을 구분하세요

- **사이트 공식 알림**: 각 사이트에 로그인해 맞춤 공고 조건(직무·지역·키워드 등)과 이메일 수신을 설정합니다. 해당 사이트가 그 계정에 등록된 주소로 발송하며, 프로젝트의 SMTP 설정이나 PC 실행과는 별개입니다. 사이트마다 지원 채널/조건이 다르므로 앱 알림만 있는 기능을 이메일이라고 설명하지 않습니다. 계정 이메일·일반 광고 수신·이력서 공개 설정은 별도이며 임의 변경하지 않습니다.
- **프로젝트 요약 메일**: 아래 절차로 인증한 주소에 검색 결과를 따로 보냅니다. 사이트 공식 알림 설정을 대신 변경하지 않습니다. 본문은 **회사명 | 직무 | 공고 기간** 3열 표이며 직무가 공고 원문 링크입니다. 플랫폼명은 회사명 아래 작게 표시하고, 긴 검색 요약·키워드 설명은 넣지 않습니다. HTML 미지원 메일에는 짧은 텍스트 목록을 제공합니다.
- 회사명은 명시된 검색 필드나 확인 가능한 제목을 사용합니다. 기간은 발송 전 읽은 원문의 마감일 또는 상시 모집 표기를 우선합니다. 원문 접수상태를 확인하지 못한 후보는 발송에서 보류합니다. 확인 후 조기 마감·변경될 수 있으므로 지원 전에는 원문을 다시 확인하세요.

본인 인증한 이메일로, 캐치·잡코리아·사람인·원티드·인크루트마다 따로 정한 조건에 맞는 **새 공고**를 정한 시간에 보냅니다. 한 번 보낸 공고 URL은 다시 보내지 않습니다.

## 동작 범위

- **이 PC 전용 기능입니다.** 로컬 작업 공간(`uv run job-agent ui`, 또는 본인 PC 연결 도구)에서만 화면과 API가 열립니다. Cloudflare 공유 방문자, `--public-demo`, Vercel 공개 웹에서는 보이지 않으며 서버도 403으로 막습니다. 검색은 운영자의 Tavily 키, 발송은 운영자의 메일 계정을 쓰기 때문입니다.
- 공개 웹에서 누구나 가입하는 알림 서비스는 아직 아닙니다. 그렇게 하려면 구독 정보 DB(Supabase 등), 메일 발송 서비스, 예약 실행(Vercel Cron 등)과 수신 거부 링크가 필요합니다.
- 잡코리아·사람인의 공개 검색 카드를 우선 수집하고, 읽기 실패 또는 미지원 플랫폼은 Tavily 웹 검색으로 대체합니다. 공식 API 연동이나 전체 공고 수집은 아닙니다. 지역·경력 적합성은 지원 전 원문에서 확인해야 합니다. [실제 품질 점검과 한계](search_quality.md)를 참고하세요.
- **발송 전 접수상태 확인**: 다섯 플랫폼의 알려진 공개 상세 주소만 읽습니다. 원문의 `JobPosting.validThrough`, 명시된 마감일·접수기간 끝 날짜, 상시/채용 시 마감 표기를 확인합니다. 마감 문구·지난 기한은 상시 문구보다 우선합니다. 게시일이 7월이라는 이유로 제외하지 않으며, 연도 없는 단독 날짜는 현재 연도로 추측하지 않습니다. 시각이 있는 마감은 한국 시간 기준으로 비교하고 발송 직전에도 기한 경과를 검사합니다.
- 로그인·차단·읽기 실패·현재 접수 근거 없음은 **상태 미확인 보류**입니다. 후보 순서대로 최대 100개를 4개 동시 요청/8개 묶음으로 확인하며, 메일 상한을 채우면 멈춥니다. 보류된 URL은 발송 완료로 기록하지 않아 다음 회차에 재확인합니다. 쿠키·계정 로그인·내부 API·차단 우회는 사용하지 않습니다. 미확인 보류로 메일 공고 수가 줄어들 수 있습니다.
- 사이트별·검색어별 최대 20건, 직무 대안은 최대 3개 검색어(추가 대안은 마지막 OR 검색에 포함)로 나눕니다. 5개 플랫폼·여러 직무는 최대 15회 검색 요청으로 기존보다 API 사용량이 늘 수 있습니다. 원문 수집 성공 시 해당 Tavily 호출은 생략합니다. 기술 키워드는 원문/요약의 근거로 필터하고, 연도와 모든 기술을 검색어에 강제로 묶지 않습니다.
- 메일 상한은 기존 설정을 유지하며 서로 다른 기업·플랫폼을 먼저 배치합니다. 미리보기/최근 실행에는 수집·조건 통과·선택 수가 표시되고, 메일의 짧은 안내에도 상한을 표시합니다. 이미 보낸 URL과 근거 부족/지역 등으로 제외한 후보를 구분해 점검하세요.
- 지역은 쉼표로 여러 곳을 적습니다(예: `서울, 경기, 판교`). `서울`·`경기`는 강남·성수·판교·분당·수원 같은 하위 지역명도 포함합니다. 검색 요약에 **다른 지역(부산·대구·인천 등)만** 적힌 공고는 빼고, 지역이 아예 안 적힌 공고는 포함하되 원문에서 확인해야 합니다. 본문은 짧은 표를 유지하므로 지역 설명은 반복하지 않습니다.
- 이미 보낸 URL과 이번 검색에서 같은 URL로 나온 공고는 중복 발송하지 않습니다. 제목이 같아도 다른 기업·채용 건일 수 있으므로 URL이 다르면 포함합니다. 같은 공고의 다른 주소는 중복될 수 있습니다. URL 기억은 최근 1000개까지 유지합니다.
- 영어·숫자 키워드(R, AI, ML 등)는 단어 단위로만 일치시킵니다(`AI`가 mail에, `R`이 아무 글자에 걸리지 않음).
- 키워드를 넣으면 제목·요약에 키워드가 하나 이상 있어야 하고, 제외 키워드가 있으면 뺍니다. 정렬은 키워드 일치 개수 순이며 적합도나 합격 가능성 판정이 아닙니다.
- AI(LLM)는 호출하지 않습니다.

## 1. 메일 발송 설정 (.env)

`resum/.env`에 아래 값을 넣고 작업 공간을 다시 실행합니다. `.env`는 Git에 올라가지 않습니다.

```dotenv
ALERT_SMTP_HOST=smtp.gmail.com
ALERT_SMTP_PORT=587
ALERT_SMTP_USER=내지메일@gmail.com
ALERT_SMTP_PASSWORD=앱비밀번호16자리
# 선택: 보내는 사람 표시(기본은 ALERT_SMTP_USER), 보안 방식(starttls 기본, 465 포트는 ssl)
# ALERT_SMTP_FROM=내지메일@gmail.com
# ALERT_SMTP_SECURITY=starttls
# ssl 또는 starttls만 허용하며, 오타가 있으면 연결하기 전에 중단합니다.
TAVILY_API_KEY=...
```

Gmail은 계정 비밀번호가 아니라 **앱 비밀번호**를 씁니다. Google 계정 → 보안 → 2단계 인증을 켠 뒤 → 앱 비밀번호에서 만듭니다. 네이버 메일은 환경설정 → POP3/SMTP 사용 후 `smtp.naver.com`, 포트 587을 씁니다.

## 2. 화면에서 등록

1. 작업 공간 왼쪽 메뉴 **공고 알림**을 엽니다.
2. **이메일 인증**: 받을 주소 입력 → **코드 보내기** → 메일로 온 6자리 코드 입력 → **인증**.
   - 코드는 10분간 유효하고 5번 틀리면 다시 받아야 합니다. 재요청은 1분 간격, 한 시간에 5번까지입니다.
   - 코드는 해시로만 저장합니다.
3. **알림 조건**: 플랫폼을 체크하고 플랫폼마다 직무·지역·키워드·제외 키워드를 넣습니다. **입력한 조건을 선택한 다른 플랫폼에 복사**로 같은 조건을 채운 뒤 플랫폼별로 고칠 수 있습니다.
4. 주기(매일·평일·매주+요일), 보낼 시각, 메일당 최대 공고 수(1~30)를 정하고 검색어 전송에 동의한 뒤 **알림 저장**.
5. **등록된 알림**에서 수정·삭제할 수 있습니다.
   - **미리보기**: 검색만 하고 메일은 보내지 않습니다.
   - **지금 보내기**: 즉시 발송합니다.
   - 인증 해제를 누르면 그 주소의 알림도 모두 삭제됩니다.

새 공고가 없으면 메일을 보내지 않고 상태에 "새 공고 없음"으로 남깁니다. 메일 발송에 실패하면 그 공고들을 보낸 것으로 기록하지 않아 다음 발송에 다시 포함됩니다.

상태 미확인 후보가 있으면 미리보기와 최근 실행 상태에 보류 수가 함께 표시됩니다. 수집 진단의 `closed`는 검색 근거에서 제외, `detail_closed`는 원문에서 제외, `status_unverified`는 상태 미확인, `detail_not_checked`는 출력 상한/확인 예산 때문에 아직 확인하지 않은 후보 수입니다. 이미 수신한 메일은 소급 수정하지 않습니다.

## 3. 언제 보내지나

- 작업 공간이 켜져 있는 동안 1분마다 발송할 알림이 있는지 확인합니다.
- PC가 꺼져 있어 시간을 놓쳤으면 다음에 켰을 때 **한 번만** 보냅니다(밀린 횟수만큼 보내지 않음).
- 작업 공간을 켜 두지 않고 보내려면 Windows 작업 스케줄러나 cron으로 아래 명령을 30분~1시간마다 실행합니다. UI와 동시에 돌아도 실행 잠금(`.run.lock`)과 저장 잠금(`.state.lock`)으로 중복 발송과 서로의 기록 덮어쓰기를 막습니다. 검색하는 동안 인증을 해제하거나 알림을 지우거나 고치면 그 회차는 보내지 않습니다.

```powershell
# 확인용
uv run job-agent alerts list
# 발송 시간이 된 알림만 실행 (작업 스케줄러에 등록할 명령)
uv run job-agent alerts run --due
# 특정 알림 미리보기 / 즉시 발송
uv run job-agent alerts run --id <알림ID> --preview
uv run job-agent alerts run --id <알림ID>
```

작업 스케줄러 예시(PowerShell, 경로는 본인 폴더로):

```powershell
schtasks /Create /SC HOURLY /TN "job-agent-alerts" /TR "\"C:\경로\resum\.venv\Scripts\python.exe\" -m job_agent alerts run --due"
```

## 저장 위치와 개인정보

- `result/job_alerts/alerts.json`(Git 제외): 인증한 이메일, 알림 조건, 마지막 실행 상태, 이미 보낸 공고 URL(최대 1000개).
- 인증 코드 원문, SMTP 비밀번호, 검색 결과 본문은 이 파일에 저장하지 않습니다.
- 검색어(직무·지역·키워드)는 Tavily로, 공고 목록은 설정한 메일 서버로 전송됩니다.
